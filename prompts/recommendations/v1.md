## Regras obrigatórias

1. Toda recomendação precisa se apoiar em um achado concreto acima. O campo
   `evidence` deve citar a métrica ou o achado de origem. **Recomendação sem
   evidência não deve ser gerada.**
2. **Nunca invente** métricas, achados, números de mercado ou dados de
   concorrentes que não estejam nos diagnósticos acima. Trabalhe **apenas com
   os dados fornecidos**.
3. **Nunca prometa** aumento de receita, de reservas ou de posição na busca.
   Use "oportunidade potencial", "recomendação", "estimativa", "hipótese".
4. `confidence` reflete a força da evidência: 0.9+ apenas quando o dado é
   direto e inequívoco; abaixo de 0.6 quando a evidência é indireta.
5. Não repita a mesma recomendação em categorias diferentes.
6. Ordene da maior para a menor combinação de impacto e facilidade de execução.
7. Produza no máximo 12 recomendações. Qualidade acima de quantidade.
8. Se um diagnóstico veio vazio, simplesmente não gere recomendações daquela
   categoria — não preencha com genéricos.

## Formato da resposta

Responda **somente** com JSON válido:

```
{
  "recommendations": [
    {
      "title": "Trocar a primeira foto",
      "description": "...",
      "category": "PHOTOS",
      "priority": "HIGH",
      "estimated_impact": "HIGH",
      "difficulty": "EASY",
      "confidence": 0.87,
      "reason": "A primeira foto tem iluminação 42/100, enquanto a foto 8 tem 89/100.",
      "action": "Colocar a foto 8 como primeira imagem do anúncio.",
      "evidence": { "current_cover_lighting": 42, "best_photo_lighting": 89 }
    }
  ],
  "strengths": ["..."]
}
```

Valores permitidos:
- `category`: `PHOTOS`, `CONTENT`, `AMENITIES`, `PRICING`, `REPUTATION`,
  `POLICIES`, `COMPETITIVENESS`
- `priority` e `estimated_impact`: `HIGH`, `MEDIUM`, `LOW`
- `difficulty`: `EASY`, `MEDIUM`, `HARD`
- `confidence`: número entre 0 e 1
